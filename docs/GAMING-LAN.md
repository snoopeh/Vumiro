# Vumiro LAN dataplane

Vumiro transports original IPv4 packets over its authenticated WebRTC data channel. Its Windows adapter uses the signed Wintun binary as a layer 3 kernel device. Vumiro owns the protocol, session lifecycle, peer validation, queues and browser bridge; no ZeroTier or WireGuard network stack runs.

Native actions are `lan-start { sessionId, address, addresses? }`, `lan-stop { sessionId }`, `lan-status`, `lan-set-peers { sessionId, addresses }`, and `lan-packet { sessionId, packet }`. Session IDs are 32 lowercase hexadecimal characters, addresses are canonical `10.203.N.H` with N=1..250 and H=1..254, and the prefix is /24. `addresses` is an array of explicitly authorized peers in that subnet. The default peer is the opposite .1/.2 endpoint (other hosts default to .1). Outbound events are `{type:"gaming-lan-packet",sessionId,packet}` with a base64 packet. The browser must bind each inbound source to the authenticated peer owning that address before delivery to native.

Start is asynchronous: poll status from `starting` to `active` or `error`. Transport connection alone does not establish adapter readiness. Windows adapter setup requires an elevated helper/process. `requiresElevation` refers to the process token; `driverReady` reports binary availability. The default trusted binary path is `runtimes/win-x64/native/wintun.dll` beneath the application directory. The elevated host can instead pass an explicit absolute path to its hash-verified extraction of the bundled signed DLL.

The adapter has a temporary /24 address, MTU 1400, no default gateway or DNS changes, and disabled forwarding/weak-host behavior. Discovery routes cover multicast and limited broadcast on this adapter. Only IPv4 UDP/TCP/ICMP with valid IPv4 lengths/checksum, an explicitly authorized source and an allowed LAN destination pass. Ordinary fragments travel unchanged for Windows to reassemble. IPv4 options/source routing are refused. Inbound destinations must be the local endpoint, subnet broadcast, limited broadcast or IPv4 multicast. Outbound unicast must target an authorized peer. Peer packets cannot target the physical LAN or internet. Windows Firewall rules still apply to games.

Inbound and outbound queues each have a 128 packet / 2 MiB ceiling. Adapter reads never wait on the UI; excess packets are counted and dropped. Retired session callbacks cannot publish. Stop cancels both pumps before the worker releases native handles. An in-progress setup operation finishes on its worker and then removes its adapter. Closing the Wintun adapter created by Vumiro removes that adapter and its temporary IP configuration.

Run nonprivileged checks using `dotnet run --project tests/GamingLanChecks/GamingLanChecks.csproj`. These use fake adapters and never create interfaces or install drivers. Optional `-- --native` smoke mode deliberately creates one temporary adapter, checks startup, then removes it. It requires elevation and the bundled Wintun DLL in the test output's fixed runtime path and is never invoked by regular tests.
