# Community service and media adapter

The local Community Hub remains a device-only demo until **Publish community** is selected. Publication sends the selected hub structure, access settings and theme bindings. It excludes local conversations, drafts and simulated members. Shared membership starts with the authenticated owner; invitations add real identities. Importing a theme or opening the workspace never publishes a community.

Source implementation and automated tests do not establish production readiness. No production infrastructure was provisioned or deployed for this change. The release process in [RELEASING.md](RELEASING.md) still applies.

## Bindings and configuration

- `COMMUNITY_HUBS`: dedicated `CommunityHub` Durable Object namespace. `wrangler.storage.jsonc` owns migration `v4-community-hubs`; `wrangler.jsonc` refers to that existing storage worker. Existing namespace names and migrations stay intact.
- `COMMUNITY_ASSETS`: private R2 bucket `vumiro-community-assets`, used by both workers. Provision the bucket before a release. Keep public bucket access disabled. Asset bodies are returned by authenticated requests, without public or presigned URLs.
- `COMMUNITY_SFU_APP_ID` and secret `COMMUNITY_SFU_APP_SECRET`: Cloudflare Realtime SFU application credentials on the storage worker. Set the App Secret with Wrangler's secret mechanism; never put it in the browser, a theme package, a URL or source control. Configure an isolated development app for service QA.

Missing storage, R2 or SFU configuration fails closed with a service-unavailable response for the affected operation. Existing direct calls keep their existing signaling path. SFU network traversal and microphone permission must be validated on the actual supported Windows/Linux environments; TURN provisioning, quotas and billing require deployment-specific configuration.

## Identity and HTTP protocol

The API is `/api/community/{hubId}/{action}`. A new hub ID is the owner's 43-character cryptographic identity, an underscore, and a random UUID. Local node IDs survive publishing; root parent IDs are rebound to the new live hub. Every HTTP operation, including history, snapshot, events, assets and media, requires a fresh signed request. Identity headers have no authority.

1. `GET /api/community/{hubId}/challenge?id={identity}` returns `{nonce, expires, hubId, id}`. A challenge expires after 30 seconds and is consumed once, including failed proofs.
2. `POST /api/community/{hubId}/{action}` contains `{id,key,nonce,payload,signature}`. `key` is a base64url SPKI P-256 public key. `id` must equal base64url SHA-256 of that key. The signature is ECDSA P-256/SHA-256 over the exact UTF-8 JSON serialization:

   ```js
   ['vumiro-community-v1', hubId, id, nonce, action, payload]
   ```

   Canonicalization here is the JSON string generated by `JSON.stringify` of this array, with payload property insertion order preserved by the sender. Challenges are bound to the hub and identity; signatures bind the action and complete payload. The browser uses the existing local profile's `profile()` and `sign()` methods.

Responses use JSON with `{error:{code,message}}` on failure. A stale structure revision returns HTTP 409 and `community-revision-conflict`; clients reload the visible snapshot before editing again. Successful message sends return durable storage acknowledgments. A network failure is not an acknowledgment; retry using the same author-scoped message ID. Reusing an ID with different text or channel returns 409.

Supported actions:

| Action | Payload / result |
| --- | --- |
| `publish` | `{hub,nodes}`; owner-only initial publication. Returns `{hubId,revision,snapshot,...}`. Repeated publication of the same owner-bound hub returns its current state. |
| `snapshot` | `{}`; returns `{hubId,id,ownerId,name,revision,nodes,members,roles,equalAuthorityModeration}`. `nodes` is an array with `id,type,kind,hubId,parentId,...`. Only accessible nodes are returned. Ordinary members receive their own membership and assigned roles. |
| `archives` | `{scopeId?}`; defaults to the hub. Returns `{hubId,scopeId,revision,nodes}` containing only archived nodes the caller can currently restore. Requires visible scope access or restore authority for an archived scope. |
| `invite` | `{memberId?,expires?,uses?}`; root role managers create a random invitation, optionally identity-bound. Default one use, 24 hours; bounded to 50 uses and seven days. Returns `{hubId,token,expires}`. |
| `join` | `{token,name?}`; a fresh proof for the joining identity and the invitation are both required. Send to the **invited hub ID**. No anonymous token-resolution endpoint exists. |
| `space-join` | `{scopeId,expectedRevision?}`; admits the authenticated hub member to a known joinable Space, after checking ancestors and explicit denies. Returns `{hubId,scopeId,status:'joined',revision,snapshot}`. Repeating an existing join does not increment the revision. |
| `space-request` | `{scopeId,expectedRevision?}`; creates an approval request for a known approval Space. Returns `{hubId,scopeId,status:'pending'\|'joined',revision}`. Repeated pending requests are idempotent. |
| `space-requests` | `{scopeId}`; requires `roles` permission at this Space and returns `{hubId,scopeId,revision,requests:[{scopeId,memberId,name,requestedAt}]}`. |
| `space-review` | `{scopeId,memberId,approve,expectedRevision?}`; requires `roles` at this Space, rechecks membership and ancestor restrictions before approval, and returns `{hubId,scopeId,memberId,status:'approved'\|'denied',revision}`. |
| `mutate` | `{expectedRevision,operations}`; atomically checks and applies up to 100 operations, then increments revision. |
| `history` | `{channelId,after?,before?,limit?}`; sequence pagination, at most 100 messages. `after` starts at zero; `before` fetches older pages. |
| `send` | `{channelId,id,text}`; 1–4,096 UTF-8 bytes. Returns `{message,duplicate}`. |
| `events` | `{after}`; at most 200 authorized events with `{events,after,resync}`. A retained-log gap requires snapshot/history recovery. |
| `moderate` | `{sequence}`; removes a message from rendered history subject to scope and authority brackets. |
| `audit` | `{after?}`; root role managers read action metadata, actor IDs and targets, without message bodies. |
| `asset-upload` | `{scopeId,contentType,data}`; base64url bytes, at most 1 MiB, permission `themes`; PNG, JPEG, WebP and WOFF2. Returns `{assetId,scopeId}`. |
| `asset-read` | `{assetId}`; authenticated bytes with `private, no-store` and a restrictive content security policy. Authorization is rechecked after awaiting R2. |

`mutate` operation forms are `{type:'node.upsert',node}`, `{type:'node.move',id,parentId,order?}`, `{type:'node.archive',id,archived}`, `{type:'theme',id,binding}`, `{type:'member.set',member:{id,roles,banned?}}`, `{type:'member.remove',id}`, `{type:'role.set',role:{id,name,authority,permissions,scopeId?}}`, and `{type:'settings',equalAuthorityModeration}`. `member.remove` records a ban so unused invitations cannot undo revocation. The owner can restore membership with `member.set`. Role permissions currently use an array of `view`, `post`, `voice`, `speak`, `moderate`, `structure`, `themes`, `roles`.

Nodes accept either `type` or the local model's `kind`; delegation accepts `managers` or `managerIds`. Access accepts local `mode`, `roleIds`, `memberIds`, `joinedMemberIds`, `invitedMemberIds`, and per-dimension allow/deny role/member lists. `joinVoice` maps to the service's `voice` permission. Hub membership is mandatory, all ancestors constrain access, and any ancestor deny persists through child allow rules. Cycles, leaf parents and invalid destinations reject the whole edit. Moves and upsert reparenting require structure permission on the source parent, the node and the destination, preventing inherited private history from being moved into an open branch by a child-only manager. Delegated managers may edit structure/themes in their branch; access, top-level permission and delegation changes require the owner. Changing a theme binding through an upsert requires theme permission just as the dedicated theme operation does. Root role managers can assign only lower authority and permissions they possess. Equal-authority moderation is disabled unless the owner enables it; owner protection remains unconditional.

The authorized archive list is separate from ordinary snapshots, search and activity. Listing and restoring evaluate structure permission with only the target's own archive flag cleared; all current ancestor restrictions and other archived ancestors remain in force. A manager can restore their own archived Space without gaining structure permission at the hub. A private archived branch never exposes its metadata to an unauthorized member. Restore an archived ancestor before listing or restoring its archived descendants. The list is read-only; restoration uses revision-checked `{type:'node.archive',id,archived:false}` in `mutate`, retaining channel IDs and history.

Known Space IDs can be shared out of band without making inaccessible content discoverable in snapshots or search. A hub member can explicitly join a `joinable` Space or request admission to an `approval` Space. The member must currently view every ancestor, and the proposed admission must still pass all explicit view denies. Invitation-only and restricted Spaces cannot be joined through these self-service actions; owners admit those members through the corresponding access lists. Approval adds only the reviewed member to that Space's `joinedMemberIds`, and cannot open an inaccessible ancestor.

Pending requests persist separately from visible snapshots, are bounded to 100 per Space and 500 per hub, and expire after 30 days. Listing/review requires the separate `roles` permission at the target Space: a scoped role can manage its Space without authority over siblings; structural delegation alone grants no request-review privilege. Approval revalidates the member's active hub membership, the Space's current approval mode, ancestor restrictions and explicit denies. Changes are atomic, audited and increment the hub revision; ordinary event streams receive only a generic revision notification, without pending identities or request details. Optional `expectedRevision` rejects stale decisions with 409. Clients must not label a local permission preview as service authorization.

## Browser text adapter

`window.VumiroCommunityLive.create({baseUrl,identity,onEvent,onState})` normalizes an existing `wss://.../call-signaling` URL to its HTTPS service origin. Construction does no networking. APIs are `publish`, `connect`, `disconnect`, `snapshot`, `history`, `send`, `mutate`, `invite`, `join`, `assetUpload`, `assetRead`, and lower-level signed `request(action,payload)`. `on(listener)` adds a removable event listener. `send(channelId,text,{id})` retains a provided idempotency ID; thrown errors include `messageId` for a retry. Profile changes and disconnected generations invalidate pending responses.

Space access convenience methods are `spaceJoin(scopeId)`, `requestAccess(scopeId)`, `accessRequests(scopeId)` and `reviewAccess({scopeId,memberId,approve,expectedRevision?})`. Each signs its action and explicit known scope. They update the adapter's known revision, and `spaceJoin` also stores its returned visible snapshot. The UI should refresh its visible snapshot after approval or access-change notifications. These actions never publish a local demo.

`archives(scopeId?)` retrieves the authorized restore list, including its revision for the subsequent restore mutation. Live authorization remains authoritative; the local effective-access preview is a planning aid and does not grant access or impersonate another member.

An invitation must convey **both** the hub ID and token. Integrations may present these as two copyable fields or encode them as app-owned query fields, for example `communityHub=<hubId>&communityInvite=<token>`; the adapter does not automatically consume navigation query parameters. Join with `live.join(token, hubId)`, which authenticates membership and then connects. The service does not redirect or resolve these query fields.

`connect(hubId)` fetches the visible snapshot and opens `wss://.../api/community/{hubId}/events?id=...`. The socket receives `community-challenge`; the client signs action `subscribe` and payload `{channelId:null}`. After `community-welcome`, it recovers the persisted event log and watched channel history. The socket is an authorized notification stream, not an identity authority or history store. Reconnect uses exponential backoff, message deduplication and history sequences. Calling `history(channelId)` changes the watched channel and returns its latest 100 messages by default, including after reconnect; pass an explicit `before` cursor for earlier pages or `after` cursor for forward recovery. A permission change closes unauthorized watched subscriptions and emits `community-revoked`; each outgoing event and every recovery read uses current authorization. Obsolete connect failures cannot alter the status of a newer connection.

Events are `community-connection` with `state`, `community-message` with `message`, `community-history` with `{channelId,messages,after,before}`, `community-message-removed`, `community-changed` with `revision`, `community-voice-changed` with `channelId`, `community-resync-required`, and `community-revoked`. Message fields are `{id,channelId,authorId,sequence,text,removed,storedAt}`.

## Separate SFU media adapter

`window.VumiroCommunityVoice.create({live,onState,onParticipants,onError,onTrack?})` owns microphone capture, PeerConnection and playback; it does not use the local simulated voice state or direct-call mesh. `join(channelId,{themeContext})`, `setMuted(boolean)`, `leave()` and `dispose()` manage the session. Theme context is explicit presentation data passed into the call surface and has no media authorization authority. Capture requests audio only; a fresh peer connection is created for each join attempt.

The backend uses Cloudflare's current [Connection API](https://developers.cloudflare.com/realtime/sfu/api/) at `https://rtc.live.cloudflare.com/v1/apps/{appId}`. [Application architecture](https://developers.cloudflare.com/realtime/sfu/concepts/architecture/) assigns authorization and secrets to the application; [negotiation and lifecycle](https://developers.cloudflare.com/realtime/sfu/concepts/negotiation/) requires ordered negotiations and cleanup of partial/late allocations.

| Action | Behavior |
| --- | --- |
| `voice-join` | `{channelId}`; reserves one active member session, checks voice access and room limit, allocates `sessions/new`, persists session ownership and checks access again afterward. |
| `voice-publish` | `{sessionId,tracks:[{mid}],sessionDescription}`; checks ownership and speaking permission, derives the microphone track name on the server, calls `tracks/new`. |
| `voice-subscribe` | `{sessionId,tracks:[{sessionId,trackName}]}`; validates every publisher and track against this hub and channel. Arbitrary SFU track/session forwarding is rejected. |
| `voice-answer` | `{sessionId,sessionDescription}`; accepts the owned pending renegotiation answer via `PUT /renegotiate`. |
| `voice-participants` | `{sessionId}`; renews a 90-second activity lease and returns accessible participants and published tracks. Browser renews every 30 seconds. |
| `voice-leave` | `{sessionId}`; retires the owned session, inspects its allocations and force-closes known tracks. |

Media mutations are serialized per session, including a pending-answer guard. Revocation retires sessions immediately and requests forced track closure; a Durable Object alarm retries failed cleanup. Browser leave/revocation stops local tracks and closes playback/PeerConnection. Each browser join reserves its generation before awaiting cleanup and retains its own hub, allocation, capture and PeerConnection; late rejection, success or microphone permission results clean only that obsolete attempt's resources. Transport loss closes local capture; abandoned backend sessions expire by lease. Cleanup metadata persists across object recreation. Per-track errors retire the session instead of authorizing partial unexpected media.

An SFU request timeout can have an uncertain outcome. Known session IDs remain retired and are inspected on subsequent cleanup alarms; the implementation retains unresolved uncertain records rather than declaring them closed. If `sessions/new` times out before returning its ID, Cloudflare provides no lookup/deduplication by correlation ID; such unknown allocations cannot be explicitly recovered by this adapter. They contain no application-authorized published tracks. Service cleanup and actual media cessation during network/provider failures require deployment QA and observability. The API deliberately does not claim that a requested forced close has already stopped all packets when Cloudflare is unreachable.

## Bounds, diagnostics and validation

Source bounds are 500 members, 2,000 nodes, 100 concurrent hub sockets and 25 active voice sessions per channel. Hub metadata is bounded to 1 MiB; a hub retains at most 100,000 message rows, 2,000 recovery events, 500 invitation records and 500 referenced assets. Quota exhaustion fails explicitly; history is not silently deleted. Audits and retained history currently need an operator retention/export policy before production scale. Orphaned R2 uploads after interrupted or revoked writes require an operator lifecycle/collection policy.

The requested targets of 500 members, 100 simultaneous text connections and 25 voice participants are **acceptance targets, not measured or advertised capacity**. Rate budgets and bounded requests reduce accidental abuse but are not a replacement for deployment-level traffic controls and monitoring. No message contents, signatures or credentials are logged by these modules; diagnostics record failure class and pending cleanup only.

Run fresh focused tests:

```powershell
node --test cloudflare/community-hub.test.js tests/community-live.test.mjs tests/community-voice.test.mjs
cd cloudflare
npm test
```

Automated tests exercise actual P-256 proofs and SQLite persistence with deterministic socket/provider fakes for service boundaries. They cover offline persistence, author-scoped idempotency, stale mutations, inherited restrictions, delegation, revocation, replay/expiry, R2 authorization races, media ownership, forced cleanup and join races. Actual Workers/R2/SFU provisioning, microphone playback, NAT traversal, concurrent multi-device operation, capacity/load measurements, Windows/Linux presentation and provider failure recovery remain release QA work.
