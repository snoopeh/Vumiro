# Community Hub

The former Servers entry opens a persistent tree of hubs, folders, independently themed Spaces, and text/voice channels. The legacy `servers` route, DOM identifiers, sandbox API and storage keys remain compatibility boundaries; unrelated backend server settings retain their names.

## Local workspace

Each signing identity owns a separate v2 local store. Existing category labels migrate into folders. Channel IDs, selected conversations, messages and drafts survive migration and moves. The old snapshot and backup remain intact; migration writes are read back before being reported saved. Storage failures keep usable edits in memory and display an unsaved status.

Select a hub or create another in Manage. Expand/collapse the tree, use arrow keys/Home/End, or search to reveal matching ancestors. Space headers and channel rows offer contextual plus/gear controls. The plus opens creation in that exact container; the gear opens scoped settings for renaming, moving, ordering, archiving and restoring. Hub settings also provide multiple-hub management. Moves retain history and drafts and reject cycles and unauthorized destinations. Homes offer compact, banner and split presets, welcome copy, announcements and featured destinations.

Scoped settings separate channel details, access, appearance and connections. Permission outcomes use readable allowed/denied rows; invitation links or codes can be pasted into Connections. Local access screens are explicitly **permission previews**. Owners configure Space access, separate operation permissions, delegated management and authority brackets. Equal-authority moderation starts disabled. Unsaved policies can be previewed for a member before saving. Simulated members and local voice previews remain labeled. They never join real calls or use the friends transport.

The community name opens a dropdown for creating text/voice channels, categories and Spaces, community settings, roles, appearance and Connections. The community switcher remains visible. Every tree row has a visible overflow button and supports right-click or Shift+F10. Menus open without rebuilding the conversation, replacing its composer or selecting the contextual channel. Arrow keys, Home and End move through menu items; Escape, Tab and clicking outside close the menu and return focus to its trigger. Categories retain the internal `folder` storage kind.

Channel menus route edit, rename and move actions to existing scoped forms; archive is reversible through settings. Containers offer scoped creation and collapse; local text channels also expose the model's mark-as-read action. Shared creation, structure and appearance entries use the service-compatible permission evaluator. Root community identity and policy editing remain owner-only, while scoped access reviewers can open admission requests. A shared invitation entry appears only with root invitation authority and calls the real invitation service. Local demos offer Connections with explicit local labeling. Shared metadata edits preserve existing permissions, managers, home configuration and theme bindings; the backend still verifies every mutation and revision.

## Themes

Community content uses a Shadow DOM styling boundary. Appearance settings retain the bundled visual collection and safe controls for finishes, message styles, corners, spacing, colors, typography and layouts. A live component preview supports desktop and narrow widths. Undo/redo, saved drafts, discard and reset make experimentation reversible. Personal simplified styling, high contrast and reduced motion apply last.

**Open full private editor** opens the shared Theme Studio for the selected local hub, Space or channel. Create, import, edit and apply your own validated packages without marketplace enrollment or review. The editor includes component styles, bounded CSS, embedded background images, WOFF2 fonts, background fit/position/repeat, desktop/narrow preview and portable export. **Apply locally** updates that scope on this device. Packages and drafts belong to the local signing identity. In a connected community, **Edit my private view** stores a separate local overlay for that identity, community and scope; it does not send a shared theme mutation.

The app's Theme Studio entry can also apply a private theme across the shell, navigation, friend list, cards, dialogs, messages, inputs and calls. This uses `VumiroLocalAppearance` and its identity-scoped package library, separate from community configuration and public profiles. Reset restores the default app appearance. Personal package kinds instead use `VumiroProfileCosmetics.applyLocal` to decorate the current user's actual avatar or card. Local creation and application require a local profile, with no marketplace account or review.

The bundled collection contains Vumiro baseline, Ember & Oak, Signal / Neon, Aurora Grove, Paper Atelier, Midnight Observatory and Rose Salon. Paper Atelier provides a light appearance. A selected theme resets the component baseline; inherited bindings preserve parent styling, then scope overrides apply. Theme and message decoration reach actual Space homes and conversations, not only thumbnails.

The local marketplace simulation can target the opened local Community Hub. Decorative packs compose with the current scope's effective appearance, preserving its base theme, layout and existing details. These bounded local compositions retain validated package bytes and support Undo; oversized compositions leave the previous binding intact. The marketplace separates installation from application: installing a personal package stores it, then **Equip on my profile** paints the current user's local avatar/card. Reset and undo remain available in My Library, and local equipment survives reload without changing anyone else's public appearance. Simulated acquisitions do not create live purchases or licensing rights.

Shared publication is a separate gate. Inheritance, app-owned builtins and validated safe overrides remain available. A custom shared theme must identify the exact reviewed marketplace item and version; raw local packages, manifests, fonts and artwork cannot authorize distribution. Publishing a local hub with an unreviewed private binding stops with a submission instruction instead of silently replacing that appearance. The service resolves approved, published, free theme/decorative packages and authenticates access when readers hydrate them. Paid shared content still requires the separate licensing/authority integration. See [the marketplace API guide](MARKETPLACE-API.md) for service configuration; nothing here deploys it.

See [the creator kit](THEME-CREATOR-KIT.md) for `.vumirotheme`, starter packages and the shared validator/packaging CLI. Private authoring and shared packages use one validator. JSON packages reject ZIP archives, scripts, arbitrary markup, external resource fetches, global selectors and geometry that could cover essential controls. Local imports remain private until an explicit, reviewed publication path accepts them.

## Shared communities

Connections offers explicit publication or connection by community ID and optional invitation token. Publishing transfers structure, access settings and theme bindings, excluding local conversations, drafts and simulated members. The conversation frame keeps its composer at the bottom while history scrolls independently. Enter sends; Shift+Enter inserts a line; IME composition does not submit. Voice rows join inline without replacing the selected conversation, and a persistent sidebar dock retains mute/disconnect and participant state. Local voice stays explicitly simulated. Narrow screens use a channel drawer.

A shared composer uses signed requests and stable retry IDs, displays durable history, recovers events, and preserves device drafts independently of the demo.

Shared Manage exposes home presets, ordering, archive discovery/restoration, access modes, delegated managers, per-role permission dimensions, authority brackets, member roles and invitations. Pending Space approvals are reviewed by authorized managers. Message removal uses service moderation and author authority checks. Shared appearance uses bundled themes or exact reviewed marketplace references. The client verifies the returned package, item/version identifiers and digest before rendering; legacy raw theme asset manifests are not hydrated. Private view overlays remain local when navigating a shared community.

The service owns persistent membership, structure, history, authorization, revision conflicts, moderation, audit records and authenticated R2 asset access. Permissions apply to every history/event/asset/media request and are checked again after asynchronous operations. Revocation closes unauthorized subscriptions and media allocations. Voice uses its own Cloudflare Realtime SFU adapter and receives theme context explicitly. Hiding the workspace stops capture and completes media cleanup before disconnecting the transport.

See [service configuration and protocol](COMMUNITY-SERVICE.md). The R2 bucket, Durable Object migration and SFU credentials require environment provisioning. Reviewed custom theme resolution also requires `MARKETPLACE_SERVICE` on the CommunityHub Durable Object owner and the same `MARKETPLACE_INTERNAL_SECRET` (at least 32 characters) on that owner and the marketplace worker. Missing review infrastructure fails closed. This implementation does not deploy services or change production data. SFU device/network behavior and the 500-member / 100-text-connection / 25-voice-participant acceptance targets require measured validation before release or capacity claims.

## Verification

- `node scripts/Check-Client.mjs --group chat` runs focused UI/model/theme/transport checks and backend tests.
- `./scripts/Run-Local.ps1` runs the full client/native gate and opens the real Windows LOCAL QA app.
- For isolated shared testing, run the local Worker as documented in [local development](LOCAL-DEVELOPMENT.md), then `./scripts/Run-Local.ps1 -LocalService`.
- `node scripts/Test-CommunityService.mjs` runs signed HTTP/WebSocket/R2 integration checks against the local Worker using generated test identities. It records counts/statuses, never credentials or message bodies, in `dist/community-service-qa.json`.
- Linux trusted-route, packaging and smoke-contract checks run in the full suite. Actual Linux app/device QA and production SFU QA remain separate acceptance work.

Automated checks and agent-operated interaction checks establish implementation readiness, not human acceptance or a release.
